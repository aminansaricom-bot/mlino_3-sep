## ۵. الزامات امنیتی (بند ۴ دستور) — پیاده و تست‌شده

1. **Existence Oracle — الزام اصلی:** `by-id` برای «ناموجود» و «سازمان دیگر» **۴۰۴ یکسان و بایت‌به‌بایت برابر** می‌دهد. تست الزامی هر دو حالت نوشته شد و بدنه‌ی پاسخ‌ها با `toEqual` مقایسه شد. همین قاعده روی مسیر ثبت تعامل هم اعمال شد (وگرنه POST خودش به یک Oracle تبدیل می‌شد) — با تست جداگانه که تایید می‌کند هیچ رویدادی هم نوشته نشده.
2. **۴۰۳ فقط برای `AuthorizationError`** — یعنی فقط واقعیتی درباره‌ی خودِ توکن، که چیزی درباره‌ی وجود اشیاء فاش نمی‌کند. هرگز برای «مجاز نیستی این فرصت را ببینی».
3. **۵۰۰ بدون جزئیات داخلی** — تست با تزریق خطای حاوی متن SQL و مسیر فایل: پاسخ فقط `{"error":"internal error"}` است و هیچ‌یک از آن رشته‌ها در آن نیست. جزئیات فقط سمت سرور Log می‌شود.
4. **۴۰۱ بی‌دلیل** — تست تایید می‌کند بدنه‌ی «توکن غایب» و «توکن بدشکل» یکسان است و هیچ اشاره‌ای به expired/signature/secret ندارد.
5. **graceful shutdown** — `close()` ابتدا Listener را می‌بندد و منتظر درخواست‌های در‌جریان می‌ماند، سپس `prisma.$disconnect()`. تست‌شده: پیش از بستن پاسخ می‌دهد، پس از بستن اتصال رد می‌شود. `server.ts` روی SIGINT/SIGTERM همین را صدا می‌زند و در برابر سیگنال دوم محافظت دارد.
