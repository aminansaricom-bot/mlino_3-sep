## زمینه

**۱. جای ارکستراسیون تجربه دو بار تغییر کرد:**
- بافت OD-26 و ردیف D-53 آن را **V2** گذاشتند.
- D-64، به دستور صریح مالک، آن را **Core** کرد.

بدون یک مرجع واحد، سند قدیمی‌تر دوباره خوانده و اجرا می‌شود.

**۲. Session در کتاب MLINO تعریف نشده بود.** در کد فقط یک JWT بی‌حالت هست (`foundation/auth-adapter/auth-adapter.ts`):
- claimها: `organization_id` · `actor_id` · `role`
- صادرکننده فقط برای تست
- بدون لغو
- وصل‌نشده به احراز هویت زنده

**۳. دو نوع دستیار با دو نوع داده:**
- **مشتری** فقط حقیقت منتشرشده را می‌بیند.
- **عضو کسب‌وکار** روی حقیقت داخلی منتشرنشده کار می‌کند — که D-52 از V2 دور نگه می‌دارد (C-06).

## تصمیم

**۱. سه لایه (D-64):**

| لایه | مسئولیت |
|---|---|
| **Core** | هوش و ارکستراسیون مستقل از کسب‌وکار |
| **V1** | حقیقت کسب‌وکار و سیستم‌عامل = **Core + ماژول‌ها** |
| **V2** | کشف، تطبیق، تعامل و تجربه |

- **ارکستراسیون تجربه و زیربنای دستیار = Core.**
- **رابط دستیار مشتری، تطبیق، کشف و رندر تجربه = V2.**
- Core **تعریف** می‌کند؛ V1 **حقیقت را نگه می‌دارد**؛ V2 **نمایش می‌دهد**.

**۲. ارکستراسیون تجربه و آفر** (روشن‌سازی مصوب مالک، ثبت‌شده روی D-53):

> ارکستراسیون تجربه مال Core است، ولی قیود D-53 همچنان حاکم‌اند. ارکستراسیون Core می‌تواند چرخه‌ی عمر تجربه را هماهنگ کند ولی آفر کسب‌وکار را نمی‌سازد، تغییر نمی‌دهد و مالکش نیست.

**خروجی ارکستراسیون برای کاربر نهایی فقط از تصویر منتشرشده ساخته می‌شود** (D-52). ارکستراسیون حقیقت نمی‌نویسد. جریان‌های صنفی را **ماژول ثبت می‌کند**؛ موتور ارکستراسیون عمومی است.

**۳. دو دستیار روی یک زیربنای Core (D-67):**

| | **دستیار مشتری** | **دستیار عملیاتی کسب‌وکار** |
|---|---|---|
| **کجا** | V2 | داخلی |
| **داده** | **فقط حقیقت منتشرشده‌ی کسب‌وکار** | **محافظت‌شده با AC-2** |
| **کار** | کشف و تجربه | کار روزمره‌ی اعضای کسب‌وکار |
| **دامنه‌ی فعلی V2** | ✅ | ❌ **بیرون از دامنه‌ی مشتری فعلی V2** |

مهارت‌های صنفی دستیار را **ماژول ثبت می‌کند**.

**۴. Session (D-66):**
- **Session مال Core است.**
- **Session فقط بافت هویت** را حمل می‌کند.
- **ماژول‌ها نمی‌توانند Session احراز هویت بسازند.**
- **اجازه از عضویت و اعطا می‌آید.**
- **Session اختیار نمی‌دهد.**

**۵. بستن Session (D-70):** **بازیابی هویت و نگه‌داشت ایمنی می‌توانند Sessionهای فعال را ببندند.** بستن Session:
- **اجازه را تغییر نمی‌دهد**
- **عضویت را تغییر نمی‌دهد**
- **اعطا را تغییر نمی‌دهد**
- **به پلتفرم اختیار کسب‌وکاری نمی‌دهد**

## پیامدها

**مستقیم از تصمیم‌های مصوب — تصمیم تازه نیستند**

| پیامد | مبنا |
|---|---|
| **سازمانِ عمل در Session حمل نمی‌شود**؛ هنگام هر درخواست با عضویت سنجیده می‌شود | D-66 («فقط بافت هویت») · D-57 (ادعای توکن مرجع عضویت نیست) |
| **پایان عضویت یا لغو اعطا منتظر انقضای Session نمی‌ماند** | D-66 (اختیار از عضویت و اعطا، نه از Session) |
| **Session جانشین برای مدیر پلتفرم وجود ندارد** — «ورود به‌جای عضو» ممنوع | D-55 (مدیر پلتفرم هیچ اجازه‌ی کسب‌وکاری — هرگز) |
| **دستیار فقط درون Session یک انسان فعال عمل می‌کند؛ کار پس‌زمینه فقط پیش‌نویس می‌سازد** (`draft`) | D-57 (نیابت ماندگار به ماشین ممنوع) · D-54 |
| **دستیار هرگز در مسیر تصمیم حاکمیتی نیست** | D-58 |
| **Session دستیار مشتری بافت سازمانی ندارد** | D-52 · D-67 |
| **حالت محلی و موقت ماژول Session نیست** — نه احراز هویت می‌کند، نه اختیار می‌دهد | D-66 |
| **ورود فعلی Content Studio هرگز در V1 احراز هویت شمرده نمی‌شود**؛ حالت نهایی ورود با هویت Core | D-62 · OD-08 |
| **حافظه‌ی گفت‌وگوی دستیار Session نیست:** گفت‌وگوی عضو = داده‌ی سازمان زیر AC-2؛ گفت‌وگوی مشتری = داده‌ی فردی ← **OD-01** | D-08 · OD-01 |

**هزینه و واقعیت پیاده‌سازی**
- JWT امروز `organization_id` و `role` را حمل می‌کند — **وضع موقت**. بازنشستگی‌اش با **OD-08** و **CCR م۱** (ADR-0011) است.
- **سازوکار لغو Session در کد وجود ندارد.** D-70 آن را به یک نیاز پیاده‌سازی تبدیل می‌کند.
- ردیف D-53 و سند آفر یادداشت D-64 گرفته‌اند؛ متن مصوب D-53 دست نخورده است.

## بدیل‌های ردشده

| بدیل | دلیل رد |
|---|---|
| **ارکستراسیون تجربه در V2** (بافت OD-26، ردیف D-53) | جایگزین‌شده با جداسازی صریح مالک — D-64 |
| **«Core ولی در سمت V2»** (خوانش OD-39) | اصلاح شد — V2 فقط رندر می‌کند |
| **ارکستراسیون آزاد از قیود D-53** | انتقال به Core قید «آفر نمی‌سازد، شرایط را عوض نمی‌کند» را دور می‌زد — روشن‌سازی مصوب مالک |
| **یک دستیار برای مشتری و عضو، هر دو در V2** | داده‌ی منتشرنشده به V2 می‌رسد — نقض D-52 |
| **V2 به‌عنوان سطح احراز‌هویت‌شده‌ی اعضا** | پالایش D-52 لازم می‌داشت — D-67 آن را نخواست |
| **Session برای هر ماژول** | سیستم احراز هویت دوم — نقض D-62 |
| **Session حامل سازمان یا نقش به‌عنوان مبنای اختیار** | ادعای توکن مرجع عضویت نیست (D-57)؛ نقش اجازه نیست (D-55) |
| **بستن Session همراه با تغییر اعطا** | بازیابی می‌افزاید و کم نمی‌کند (D-58) — D-70 |

| **D-57** | ✅ **تقویت** | اختیار از عضویت و اعطا؛ ادعای توکن مرجع نیست؛ نیابت ماندگار به ماشین ممنوع — در لایه‌ی Session اجرا شد. D-70 هیچ اعطایی را تغییر نمی‌دهد |
