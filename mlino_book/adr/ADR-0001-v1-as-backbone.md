# ADR-0001 — V1 به‌عنوان ستون فقرات و هویت متعارف

**وضعیت:** مصوب · **تاریخ:** ۹ سپتامبر ۲۰۲۶ · **تصمیم‌گیرنده:** مالک محصول

---

## زمینه

چشم‌انداز MLINO V1 را به یک سیستم‌عامل کسب‌وکار گسترش داد. ممیزی نشان داد دو سیستم واقعی و مستقل وجود دارند که هر دو می‌توانند نامزد ستون فقرات باشند:

| | V1 (`implementation/`) | Content Studio |
|---|---|---|
| هویت | `CoreEntity` + organization | `workspace` |
| حاکمیت دسترسی | **AC-2 — ساخته و بازبینی‌شده** | ندارد |
| مدل | Event-sourced | جدول‌محور |
| اتصال به داده‌ی واقعی | سمت خواندن بله، سمت تشخیص **نه** | بله |
| سنجش نتیجه | ندارد | **دارد** |
| تست | ۱۶۲ | ۴۵۶ |

هرکدام دقیقاً همان چیزی را دارد که دیگری ندارد.

## تصمیم

**V1 ستون فقرات هویت، سازمان، حاکمیت و Business OS باقی می‌ماند.**

**Content Studio به‌عنوان MLINO V1 Content & Social Intelligence Module** ادامه می‌یابد — نه یک محصول موازی، نه رقیب.

`organization` در V1 = **هویت متعارف کسب‌وکار**.

## دلایل

**۱. AC-2 سخت‌ترین بخش است و از قبل ساخته شده.** بند ۸ چشم‌انداز (مرز داخلی/قابل‌انتشار) یک الزام امنیتی است، نه یک قابلیت. V1 آن را دارد، fail-closed است، existence oracle‌اش در مرز HTTP بسته شده، و بازبینی مستقل شده. بازسازی این روی Content Studio یعنی دوباره ساختن گران‌ترین و پرخطرترین بخش.

**۲. مدل event-sourced برای حافظه‌ی سازمانی مناسب‌تر است.** بند ۱ چشم‌انداز «تصمیم‌های گذشته» و «تاریخچه‌ی عملکرد» می‌خواهد. Event Log دقیقاً همین است.

**۳. آنچه Content Studio دارد و V1 ندارد، قابل انتقال از راه قرارداد است.** حلقه‌ی یادگیری بازنویسی نمی‌شود؛ از راه قرارداد C به V1 حرف می‌زند.

**۴. تعداد تست معیار نیست.** ۴۵۶ در برابر ۱۶۲ به‌نظر قاطع می‌آید، ولی این‌ها دو دامنه‌ی متفاوت را می‌سنجند. آنچه اهمیت دارد این است که کدام سیستم **قیود سخت** را دارد.

## پیامدها

**مثبت:** هیچ بازنویسی · AC-2 نقطه‌ی واحد کنترل می‌ماند · هر دو سیستم به کار خود ادامه می‌دهند

**منفی / هزینه‌ها:**
- Content Studio باید برای هر عمل نیازمند هویت، به V1 مراجعه کند → یک وابستگی جدید
- نگاشت `workspace ⇄ organization` باید ساخته و نگهداری شود
- **دو پشته (TS و Python) باقی می‌مانند** — این هزینه‌ی واقعی نگهداری است و پذیرفته شده

**آنچه این ADR تصمیم نمی‌گیرد:** ادغام فیزیکی مخازن (→ ADR-0002) و ادغام کد دو موتور (→ ADR-0003).

## بدیل‌های رد‌شده

**Content Studio به‌عنوان ستون فقرات** — رد شد چون AC-2 و مدل رویداد باید از صفر ساخته می‌شدند.

**ساخت یک هسته‌ی سوم** — رد شد چون هر دو سیستم موجود را به میراث تبدیل می‌کرد؛ نقض مستقیم اصل `Reuse → Wrap → Integrate`.
