## ۳. مهم‌ترین یافته‌ی ممیزی — تکرار موتور اقدام

دو پیاده‌سازی مستقل از یک مفهوم بالادستی وجود دارد:

| | V1 `value-engines/` | Content Studio `learning/` |
|---|---|---|
| زبان | TypeScript | Python |
| ورودی | رویدادهای عملیاتی (لغو نوبت، ظرفیت، پیگیری) | عملکرد واقعی محتوای منتشرشده |
| خروجی | Opportunity | Recommendation |
| سنجش نتیجه | ندارد | **دارد** — `outcomes` + `evaluations` |
| اتصال به دیتابیس | **ندارد** (In-Memory) | **دارد** |
| حاکمیت دسترسی | **دارد** (AC-2) | ندارد |

هرکدام دقیقاً همان چیزی را دارد که دیگری ندارد. این تصادفی نیست — دو تیم مسئله‌ی یکسانی را از دو سر حل کرده‌اند.

**تصمیم:** هیچ‌کدام حذف نمی‌شود. اول قرارداد مشترک تعریف می‌شود، سپس هر دو به آن حرف می‌زنند. ادغام کد فقط با توجیه. → [`adr/ADR-0003`](adr/ADR-0003-shared-recommendation-contract.md)

## ۳.۱. جایگاه Content Studio در MLINO V1

```
Content Studio
      ↓
MLINO V1 Content Intelligence Module
      ↓
Business Intelligence
      ↓
AI Business Operating System
```

**ولی MLINO V1 فقط Content Studio نیست.** Content Studio اولین ماژول عملیاتی است، نه کل محصول.

**آنچه به مرور به آن وصل می‌شود:** چشم‌انداز کسب‌وکار · هویت برند · محصولات · خدمات · بینش مشتری · اهداف · KPI · داده‌ی عملکرد · رویدادهای کسب‌وکار

**آنچه در ازایش می‌دهد:** استراتژی محتوا · تولید محتوا · برنامه‌ریزی کمپین · مدیریت شبکه‌های اجتماعی · هوش پاسخ به مشتری · یادگیری از عملکرد

**قید:** پیش از هر توسعه، معماری فعلی حفظ و قابلیت‌های موجود نگاشت می‌شوند. **بازسازی نمی‌شود.**

## ۴. هویت کسب‌وکار — سلسله‌مراتب متعارف

```
                MLINO Business ID
                       │
       ┌───────────────┼───────────────┐
       │               │               │
V1 Organization   Content Studio   V2 Business Twin
  (canonical)       workspace       (نمای مشتری‌رو)
```

**V1 Organization منبع حقیقت متعارف است.** دو تای دیگر **نمایندگی محلی**‌اند و هیچ‌کدام مالک هویت کسب‌وکار نیستند:

- **Content Studio `workspace`** — لنگر چندمستأجری ماژول محتوا؛ از راه نگاشت صریح، قطعی و قابل‌ممیزی وصل می‌شود، نه بر اساس نام، نه ضمنی. → ADR-0004
- **V2 Business Twin** — نمای مشتری‌روی همان کسب‌وکار، همیشه از پشت AC-2. هیچ فیلدی که در قرارداد `02` نیست، در آن وجود ندارد.

**Content Studio نباید هویت کسب‌وکار مستقل بسازد.** این قید صریح و قطعی است.

## ۴.۱. موتور اقدام روزانه — یکی از هسته‌های V1

بند ۳ چشم‌انداز یک **هسته** است، نه یک داشبورد. تفاوت در این است که هر اقدام باید پنج چیز داشته باشد، وگرنه اصلاً نمایش داده نمی‌شود:

| الزام | چرا |
|---|---|
| **دلیل / شواهد** | بدون آن، یک حدس است |
| **مسئول** | بدون آن، هرگز انجام نمی‌شود |
| **اثر انتظاری** | بدون آن، اولویت‌بندی ممکن نیست |
| **KPI مرتبط** | بدون آن، به هیچ هدفی وصل نیست |
| **نتیجه‌ی قابل‌اندازه‌گیری** | بدون آن، هرگز یاد نمی‌گیریم |

این پنج مورد دقیقاً همان فیلدهای اجباری قرارداد C هستند. **داشبوردی که فقط عدد نشان دهد، این تعریف را برآورده نمی‌کند.**
