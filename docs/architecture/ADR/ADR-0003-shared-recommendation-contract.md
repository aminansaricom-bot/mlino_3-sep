# ADR-0003 — قرارداد مشترک پیشنهاد به‌جای ادغام موتورها

**وضعیت:** مصوب · **تاریخ:** ۹ سپتامبر ۲۰۲۶

---

## زمینه

ممیزی نشان داد «موتور اقدام روزانه» (بند ۳ چشم‌انداز) **دو بار** پیاده شده:

| | `implementation/value-engines/` | `CONTENT STUDIO/service/app/learning/` |
|---|---|---|
| زبان | TypeScript | Python |
| ورودی | رویداد عملیاتی | عملکرد واقعی محتوا |
| خروجی | Opportunity | Recommendation |
| **سنجش نتیجه** | ❌ | ✅ `outcomes` + `evaluations` |
| **اتصال به دیتابیس** | ❌ In-Memory | ✅ |
| **حاکمیت دسترسی** | ✅ AC-2 | ❌ |

## تصمیم

**هیچ‌کدام حذف یا بازنویسی نمی‌شود.**

یک **قرارداد بالادستی مشترک** تعریف می‌شود که هر دو از راه Adapter به آن حرف می‌زنند. ادغام کد فقط با توجیه مستقل و بعداً.

### چه چیزی canonical است

| جزء | تصمیم |
|---|---|
| شِمای قرارداد | Canonical — یک تعریف، در V1 |
| هویت کسب‌وکار | Canonical — organization در V1 |
| حاکمیت دیده‌شدن | Canonical — AC-2 |
| هر دو موتور | Adapter — مدل داخلی دست‌نخورده |

## دلایل

**۱. هرکدام چیزی دارد که دیگری ندارد.** ادغام یعنی انتخاب یکی و از دست دادن قابلیت‌های دیگری، یا بازنویسی هر دو. قرارداد یعنی نگه‌داشتن هر دو.

**۲. ادغام زودهنگام قبل از فهمیدن مفهوم مشترک، ریسک بالایی دارد.** ممیزی نشان داد مفاهیمی مثل `target_role`، `expected_impact` و `effort` در **هیچ‌کدام** وجود ندارند. اول باید مفهوم درست تعریف شود.

**۳. Adapter برگشت‌پذیر است.** اگر تعریف قرارداد اشتباه بود، فقط لایه‌ی نگاشت عوض می‌شود، نه دو موتور کاری.

**۴. اصل پروژه.** `Reuse → Wrap → Integrate → Consolidate (فقط با توجیه)`.

## پیامدها

**مثبت:** صفر بازنویسی · هر دو موتور به کار ادامه می‌دهند · قرارداد شکاف‌های مفهومی را آشکار می‌کند · حلقه‌ی یادگیری حفظ می‌شود

**منفی:**
- یک لایه‌ی نگاشت اضافه در هر طرف
- دو مدل داخلی همچنان جدا نگهداری می‌شوند
- **رتبه‌بندی بین‌منبعی تعریف نشده** — تا آن موقع فهرست فقط گروه‌بندی می‌شود، نه رتبه‌بندی (→ OD-06)

## سه قاعده‌ی سخت قرارداد

۱. **هیچ پیشنهادی بدون شواهد** — حداقل یک `evidence` با اشاره به رکورد واقعی
۲. **هیچ پیشنهادی بدون مسئول** — `target_role` اجباری
۳. **دیده‌شدن همیشه از AC-2** — هیچ مصرف‌کننده‌ای مستقیم از جدول نمی‌خواند

## شرایطی که ادغام واقعی را توجیه می‌کند

این ADR ادغام را برای همیشه رد نمی‌کند. ادغام وقتی بررسی می‌شود که:

۱. هر دو Adapter مدت معناداری کار کرده باشند و قرارداد پایدار شده باشد
۲. نگهداری دو مدل داخلی هزینه‌ی واقعی و اندازه‌گیری‌شده ایجاد کند
۳. رتبه‌بندی بین‌منبعی تعریف شده باشد (OD-06)

**تا آن موقع، ادغام یک بهینه‌سازی زودهنگام است.**
