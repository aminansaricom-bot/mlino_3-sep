## ۱. چه چیزی ساخته شد

چت با دستیار تطبیق نیاز داخل همان اپ فاز ۱ (`mlino2/app/`) — تب جدید «دستیار»:

| مسیر | نقش |
|---|---|
| `app/src/matching/normalize.ts` | نرمال‌سازی فارسی (عربی→فارسی، نیم‌فاصله، اعراب، پسوندهای سبک) |
| `app/src/matching/IntentParser.ts` | `RuleBasedIntentParser` — فهم نیت: دسته، کلیدواژه‌ها، modifierها (تخفیف/ارزان/نزدیک‌ترین)، شعاع متنی («تا ۲ کیلومتر») |
| `app/src/matching/MatchingService.ts` | رتبه‌بندی: فیلتر جغرافیایی (از `BusinessDirectoryService.findNear`) + امتیاز شباهت متنی + بوست آفر/نزدیکی |
| `app/src/matching/container.ts` | سیم‌کشی وابستگی‌ها — MatchingService فقط از Directory داده می‌گیرد (سند `01` بخش ۲) |
| `app/src/matching/matching.test.ts` | ۱۴ تست جدید فاز ۲ |
| `App.tsx` / `index.css` | تب «کسب‌وکارها / دستیار»، چت دوطرفه، کارت‌های نتیجه، نقطه‌ی جست‌وجو (موقعیت من / دابل‌کلیک نقشه)، انتخاب شعاع، مارکر طلایی نتایج روی نقشه |

### قابلیت‌های قابل‌نمایش

- چت فارسی: «دنبال جرم‌گیری دندان می‌گردم» → کلینیک لبخند پارس + محصول منطبق + قیمت
- نمایش صریح «چه فهمید» (دسته/کلیدواژه‌ها/شعاع) زیر هر پاسخ — شفافیت، نه جعبه‌سیاه
- کارت نتیجه: فاصله، دسته، طبقه (در مکان چندطبقه)، محصولات منطبق، آفر فعال
- کلیک روی کارت → پروفایل + پرواز نقشه به مارکر؛ نتایج آخرین پرسش با مارکر طلایی
- **دامنه گسترش یافت** (طبق نقشه‌راه فاز ۲): کافه، رستوران، فروشگاه به داده‌ی Mock اضافه شدند — ۱۰ کسب‌وکار؛ کافه در همکف پاساژ (برای تمرین فیلتر طبقه با طبقه‌ی ۰)

## ۲. تصمیمات فنی و چرا

| تصمیم | چرا |
|---|---|
| **فهم نیت قاعده‌محور (قاموس مترادف فارسی + نرمال‌سازی) به‌جای LLM** | **وابستگی صریح: به API Key/سرویس‌دهنده‌ی LLM نیاز است که موجود نیست.** طبق انضباط پروژه (خودت فرض نکن، صریح اعلام کن) به‌جای انتظار، پارسر تعیین‌کننده‌ی آفلاین ساختم: کاملاً تست‌پذیر، بدون هزینه/شبکه/حریم‌خصوصی-خروجی. این با سند `01` بخش ۵ سازگار است: «می‌تواند از LLM استفاده کند» — اختیاری بود، نه الزام. |
| **`IntentParser` به‌صورت Interface-محور** | وقتی مالک محصول LLM تصویب کرد (سوال باز بخش ۶)، فقط یک `LlmIntentParser` با همان Interface اضافه می‌شود؛ MatchingService و UI دست نمی‌خورند. خروجی هر دو همان `ParsedIntent` است. |
| **تضمین ضدتوهم در معماری، نه در متن گزارش** | پارسر فقط «پارامتر جست‌وجو» تولید می‌کند؛ MatchingService فقط رکوردهای واقعی Directory را رتبه می‌دهد؛ تست «هر نتیجه قابل‌ردیابی به رکورد واقعی» این را قفل می‌کند. دستیار به‌طور ساختاری نمی‌تواند محصولی اختراع کند. |
| **رفع یافته‌ی یونس همین حالا** | whitelist دسته‌ها در `validate.ts` (بخش ۲ پیام یونس) + تست جدید: مقدار `category` خارج از لیست قرارداد draft-1 حالا در ورود Snapshot رد می‌شود، نه اینکه بی‌صدا وارد Cache شود. |
| شباهت معنایی = تقریب واژگانی (مترادف+ریشه‌یابی سبک) | صادقانه: این «معنایی کامل» نیست — Embedding واقعی نیازمند تصمیم LLM/سرویس است. محدودیت فعلی: پوشش قاموس محدود به دامنه‌ی داده‌ی Mock است؛ عبارات خیلی غیرمستقیم ممکن است match نشوند (پارسر صادقانه null برمی‌گرداند، حدس جعلی نمی‌زند). |
