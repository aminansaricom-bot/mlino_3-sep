# HANDOFF/ — گزارش‌های تحویل موجی روی MLINO V2

هر بار که موجی یک بخش قابل‌توجه از کار را تحویل می‌دهد، یک فایل گزارش جدید اینجا اضافه کند — با نام `YYYYMMDD_<عنوان_کوتاه>_REPORT.md`.

هر گزارش باید شامل باشد:
- چه چیزی ساخته شد (فهرست دقیق فایل‌ها/قابلیت‌ها)
- چه تصمیم فنی مهمی گرفته شد و چرا (مخصوصاً اگر از پیشنهادهای `01_ARCHITECTURE_PRINCIPLES.md` منحرف شده)
- چه چیزی هنوز Placeholder/ناقص/Mock است — صریح و بدون اغراق
- آیا `02_V1_V2_INTEGRATION_CONTRACT_DRAFT.md` نیاز به تغییر داشت یا نه
- تست‌های اجراشده و نتیجه‌شان
- سوال/تصمیم باز برای مالک محصول (اگر هست)

این پوشه از `AI_HANDOFF/` (که مخصوص V1 است) کاملاً جداست — این دو مسیر توسعه موازی و مستقل گزارش می‌دهند.

## NEXT_INSTRUCTION_FOR_MOJI.md

بازخورد/دستور بعدیِ مالک محصول (یا بررسی فنی یونس، به درخواست مالک محصول) برای موجی، همیشه در همین فایل — `mlino2/HANDOFF/NEXT_INSTRUCTION_FOR_MOJI.md` — نوشته می‌شود و هر بار Overwrite می‌شود (تاریخچه‌ی نسخه‌های قبلی همان‌طور که هست در Git History باقی می‌ماند). موجی قبل از هر ادامه‌ی کار، این فایل را می‌خواند. این یک پروتکل رسمی با تطبیق چک‌سام مثل `AI_HANDOFF/CODEX_NEXT_INSTRUCTION.md` نیست — سبک‌تر است، چون V2 هنوز پروتکل بازبینی مستقل رسمی خودش را ندارد.
