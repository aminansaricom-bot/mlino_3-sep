# گزارش جلسه‌ی راستی‌آزمایی زنده‌ی LLM — اتصال واقعی، fallback زنده، مقایسه، E2E مرورگر

**تاریخ:** ۶ سپتامبر ۲۰۲۶
**نویسنده:** موجی (GLM 5.3 Flash)
**دستور فعال:** بازبینی تاییدشده‌ی LlmIntentParser (۷۴/۷۴ مستقل) + دستور ۶بندی جلسه‌ی زنده
**کلید:** DeepSeek از مالک — فقط در `.env.local` محلی (gitignored با `*.local`)؛ **هیچ Secret ای در این گزارش/Commit نیست.**

## خلاصه‌ی اجرایی

همه‌ی ۶ بند اجرا شد. اتصال زنده‌ی DeepSeek موفق؛ fallback زنده در دو سطح (سرویس و UI) اثبات شد؛ **یک باگ واقعی کشف و رفع شد** (`envPrefix` — کلید هرگز به اپ نمی‌رسید)؛ **یک ضعف واقعی پارسر قاعده‌محور توسط LLM آشکار شد** (تطبیق تساوی توکن — «پیتزای» به «پیتزا» نمی‌خورد)؛ هزینه و تاخیر واقعی ثبت شد؛ E2E مرورگر ۹/۹.

## ۲. یافته‌ی آشکارشده توسط LLM — ضعف قاعده‌محور (برای بند ۴)

**تطبیق تساوی توکن، نه زیررشته:** «پیتزای**ـ**» (صرف مالکی) ≠ «پیتزا» → دسته null. LLM همان را restaurant فهمید. عیناً با tsx دیباگ شد: stems=`[پیتزای، مخصوص، …]`. **رفع نشد** (خارج از دامنه‌ی این پاس) — پیشنهاد: `includes` در `textScore`/قاموس یا افزودن صرف‌ها به قاموس. تصمیم با بازبینی/مالک.

## ۳. fallback زنده (بند ۲) — هر دو سطح

| سناریو | نتیجه‌ی عینی |
|---|---|
| کلید عمداً غلط (Node) | `source=rule-based, fellBackToRule=true, usage=null` — LLM امتحان شد (401 در ~844ms) → قاعده‌محور. فایل: `out/live-fallback.json` |
| کلید غلط در **UI مرورگر** | پاسخ دستیار صادقانه: «موتور: **قاعده‌محور (fallback از LLM)**» — ۸.۶s (تاخیر retry/TLS قبل از 401)؛ ۹/۹ گام سبز |
| اتصال سالم (کنترل) | `source=llm, usage={300+56}` در ۱۳۳۸ms |

## ۴. تاخیر و هزینه (بند ۳ — داده‌ی تصمیم پلن‌بندی)

- **۷ فراخوانی زنده‌ی LLM:** تاخیر min/median/max = **789 / 854 / 1648ms** (فقط یک نمونه بالای ۱.۶s — احتمالاً cold-start اولین درخواست).
- **توکن واقعی هر فراخوانی:** ورودی ۲۸۰–۳۰۰ (~۲۹۰ میانگین؛ systemPrompt ثابت ~۲۵۰ توکن + جمله‌ی کوتاه)، خروجی ۴۸–۵۹ (~۵۴ میانگین).
- **قیمت تخمینی deepseek-chat** (نرخ رسمی لحظه‌ی گزارش، Input-cache-miss $0.27/M، Output $1.10/M): هر فراخوانی ≈ **$0.000138** (~۰٫۱۴ سنت/هزار فراخوانی ≈ **$0.14 در ۱۰۰۰ نیت LLM**). با cache-hit ورودی ($0.07/M) نصف می‌شود.
- **Edge-first اثبات شد:** ۳/۱۰ جمله صفر توکن، صفر تاخیر شبکه.
- مقیاس‌پذیری: ۱۰هزار کاربر × ۳ نیت LLM/روز ≈ **$4.2/ماه** — LLM گلوگاه هزینه نیست؛ تصمیم نهایی با مالک.

## ۵. E2E مرورگر واقعی (بند ۵) — ۹/۹ ✅ ×۲ سناریو

Edge واقعی (headless) روی `dev` HTTP محلی: load → تب دستیار → ارسال جمله → پاسخ دستیار (بج موتور) → کارت‌های نتیجه → کلیک → پروفایل → بج «داده‌ی آزمایشی» → اسکرین‌شات.
- **سناریوی زنده:** «موتور: LLM (deepseek:deepseek-chat)»، کافه مکث → پروفایل ✅
- **سناریوی fallback:** «موتور: قاعده‌محور (fallback از LLM)» ✅

## ۶. باگ کشف‌شده و رفع‌شده در همین جلسه — `envPrefix` ⚠️

تست E2E اول **شکست خورد** و باگ واقعی را آشکار کرد: بج UI می‌گفت «قاعده‌محور روی دستگاه» و LLM صدا نمی‌شد — **Vite به‌طور پیش‌فرض فقط `VITE_*` را به `import.meta.env` می‌رساند**؛ متغیرهای `V2_*` هرگز به اپ نمی‌رسیدند (کلید زنده فقط در اسکریپت‌های Node کار می‌کرد چون `process.env` می‌خواندند).
**رفع:** `envPrefix: ['VITE_', 'V2_']` در `vite.config.ts` + تست مجدد E2E (هر دو سناریو ۹/۹). **درس:** راستی‌آزمایی زنده دقیقاً برای همین است — تست‌های Mock این را نمی‌توانستند ببینند.
- `.gitignore` نیز `scripts/local/` گرفت (اسکریپت‌های زنده/خروجی/فایل‌های با کلید هرگز Commit نمی‌شوند؛ `.env.local` از قبل با `*.local` پوشیده بود).
