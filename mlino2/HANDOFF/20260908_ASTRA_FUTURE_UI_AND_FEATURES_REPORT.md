# تحویل مرحله‌ی رابط آینده MLINO و تجربه‌های محلی

**شاخه:** `astra/visual-system-local-experience`  
**وضعیت:** آماده‌ی بازبینی کلاد؛ هنوز روی `main` ادغام نشده

## ساخته‌شده

### Asset pack مستقل

- `app/src/design/icon-paths.json` منبع واحد مسیرهای SVG است.
- `app/src/design/Icon.tsx` آیکون‌های کنترل‌شده، سکه‌ی دسته و `iconMarkup` را ارائه می‌کند.
- `app/scripts/build-asset-pack.mjs` بسته‌ی SVG و گالری `public/mlino-assets/` را تولید می‌کند.
- ۲۷ SVG مستقل برای فرمان‌ها، دسته‌ها، وضعیت‌ها و کنترل‌ها تولید شد.
- این‌ها آیکون دسته‌اند و لوگوی واقعی هیچ کسب‌وکاری نیستند.

### تجربه‌ی محلی کاربر

- `فضای من` با دو مجموعه‌ی «مکان‌های من» و «بعداً ببینم»
- ذخیره‌سازی نسخه‌دار در `localStorage` با داده‌ی خراب/ناامن‌نشده به حالت خالی برمی‌گردد.
- «کمتر نشان بده» برای کنارگذاشتن یک رکورد در مرورگر
- ثبت مشاهده‌ی ویترین به‌عنوان تعامل داخل اپ؛ هرگز به معنی بازدید حضوری نیست.
- پیشرفت سه مأموریت محلی، بدون امتیاز جعلی، رتبه‌بندی یا جایزه‌ی مالی
- تغییر ظاهر پنل‌ها، صدای کوتاه و بازخورد لمسی به‌صورت اختیاری
- markerهای نقشه، سکه‌های AR و جزئیات از زبان SVG مشترک استفاده می‌کنند.

## تست

```text
npm test -- --run
Test Files: 6 passed
Tests: 97 passed

npm run build
موفق
```

تست مرورگری Playwright در محیط اجرا به‌دلیل نبود Chromium محلی و timeout/502 در دانلود مرورگر اجرا نشد؛ این مانع در گزارش شفاف ثبت شده و نباید با تست Vitest جایگزین تلقی شود. اسکرین‌شات کانسپت تولیدی فقط مرجع بصری است و به‌عنوان خروجی واقعی اپ ادعا نمی‌شود.

## درخواست قضاوت کلاد

1. آیا `فضای من` و ذخیره‌سازی محلی، بدون ساختن هویت کاربری پنهان، قابل قبول است؟
2. آیا مأموریت‌های «مشاهده‌ی داخل اپ» مرز صداقت داده را حفظ کرده‌اند؟
3. آیا asset pack SVG، selectorها و افزودن state در `App.tsx` با کار موجی تعارض آینده ایجاد می‌کند؟
4. آیا پیش از ادغام، اجرای تست مرورگری باید به یک ابزار/CI رسمی تبدیل شود؟
5. آیا CRهای جدول باید در یک سند معماری واحد جمع شوند یا هر قابلیت سند جدا داشته باشد؟
