# Change Request — پیشنهاد ساعتی و حباب زنده در نقشه و AR

**تاریخ:** ۸ سپتامبر ۲۰۲۶  
**وضعیت:** نیازمند قضاوت کلاد؛ کدنویسی متوقف تا تصمیم معماری

## مسئله

مالک محصول می‌خواهد کسب‌وکار بتواند پیشنهاد کوتاه‌مدت یا ساعتی منتشر کند؛ کاربران نزدیک آن پیشنهاد را هم روی نقشه و هم در ویترین AR ببینند. در AR، از محل کسب‌وکار حباب یا ذرات تخفیف به سمت بالا حرکت کند.

## چرا با داده‌ی فعلی قابل‌اتکا نیست

دایرکتوری V2 می‌تواند پیشنهادهای موجود در رکورد کسب‌وکار را بخواند، اما برای انتشار زنده به این اطلاعات نیاز است:

- شناسه‌ی پایدار کسب‌وکار و پیشنهاد
- زمان شروع و پایان معتبر، همراه با منطقه‌ی زمانی
- وضعیت انتشار و لغو پیشنهاد
- محدوده‌ی نمایش و سیاست حریم خصوصی موقعیت
- نسخه یا timestamp برای جلوگیری از نمایش پیشنهاد منقضی
- منبع معتبر رویداد و مسیر احراز هویت کسب‌وکار

بدون این موارد، انیمیشن AR فقط ظاهر جذاب خواهد بود و نمی‌توان ادعا کرد پیشنهاد واقعاً زنده است.

## پیشنهاد اولیه برای قضاوت

یک رکورد رویداد جدا از پروفایل کسب‌وکار، با نام مفهومی `LiveOfferEvent` (نام نهایی با مالک قرارداد است) که حداقل شامل موارد زیر باشد:

```text
event_id
business_id
offer_id
title
discount_percent | null
starts_at
expires_at
status: active | cancelled | expired
visibility_radius_meters
published_at
```

V2 فقط رویدادهای معتبر و فعال را از یک API خواندنی دریافت کند. Matching و Map می‌توانند همان `business_id` را مصرف کنند؛ AR فقط رویداد فعال را در شعاع AR و میدان دید فعلی نمایش دهد. انیمیشن، مشتق بصری همین رویداد باشد و خودش داده تولید نکند.

## تصمیم‌هایی که کلاد باید بررسی کند

1. آیا این داده باید به قرارداد V1/V2 اضافه شود یا یک API read-only مستقل برای V2 لازم است؟
2. آیا `visibility_radius_meters` تصمیم کسب‌وکار است یا باید توسط سیاست محصول محدود شود؟
3. آیا نمایش پیشنهاد برای کاربران اطراف نیازمند رضایت یا تنظیم جداگانه‌ی موقعیت است؟
4. TTL، cache و رفتار قطع اینترنت چه باشد تا پیشنهاد منقضی روی نقشه یا AR باقی نماند؟
5. آیا انیمیشن «حباب‌های رو به آسمان» از نظر عملکرد موبایل و دسترس‌پذیری باید فقط برای پیشنهاد فعال و حداکثر یک کسب‌وکار اصلی اجرا شود؟
6. آیا این CR با `02_V1_V2_INTEGRATION_CONTRACT_DRAFT.md` یا قراردادهای منجمد تعارض دارد؟ اگر بله، دقیقاً کدام تغییر رسمی لازم است؟

## تصمیم اجرایی استرا

تا ثبت تصمیم کلاد، هیچ فیلد جدیدی به قرارداد، هیچ API جدیدی به V1 و هیچ event ساختگی به داده‌ی آزمایشی اضافه نمی‌شود. UI فعلی فقط پیشنهادهایی را نشان می‌دهد که همین حالا در رکورد واقعی دایرکتوری وجود دارند.

## پذیرش بعدی

پس از پاسخ کلاد، این CR باید به یکی از این مسیرها تبدیل شود:

- **تأیید Frontend-only:** فقط اگر داده‌ی لازم همین حالا در قرارداد موجود باشد.
- **CR قراردادی/Backend:** اگر منبع رویداد، زمان‌بندی، انتشار یا احراز هویت لازم باشد.
- **رد یا محدودسازی:** اگر ارزش تجربه از هزینه و ریسک حریم خصوصی بیشتر نباشد.
