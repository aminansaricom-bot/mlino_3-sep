## ۲. دستور فعال — اتصال زنده‌ی DeepSeek + تست زنده

### ۲.۱. اتصال زنده (با کلیدی که داری)
1. کلید DeepSeek که داری فقط در `env` محلی (`*.local` — gitignore شده) — **هرگز در ریپو/Commit/گزارش/لاگ.**
2. چرخه‌ی کامل را زنده اجرا کن: جمله‌ی کاربر → `LlmIntentParser` (DeepSeek) → اعتبارسنجی قرارداد → `MatchingService` → نتیجه روی UI. چند جمله‌ی واقعی فارسی از دامنه (دندان/زیبایی/کافه/رستوران/فروشگاه) تست کن و نتیجه‌ی هر کدام را ثبت کن.
3. **تست fallback زنده هم** — یک بار با کلید اشتباه یا قطع شبکه، ببین واقعاً به قاعده‌محور برمی‌گردد و UI صادقانه «fallback» نشان می‌دهد.
4. **ثبت هزینه و تاخیر:** برای هر فراخوانی زنده، تاخیر (ثانیه) و تخمین توکن/هزینه را در گزارش بیاور — این داده مستقیم تصمیم پلن‌بندی مالک است.
5. مقایسه‌ی LLM در برابر قاعده‌محور روی همان جملات (جدول) — کجا LLM بهتر بود، کجا فرقی نکرد.

### ۲.۲. تست زنده‌ی برنامه (همان جلسه یا بلافاصله بعد)
با `npm run dev:https` (که تایید شده) یا HTTP محلی:
- یک چرخه‌ی کامل «دستیار»: جمله → پاسخ → کارت‌های نتیجه‌ی واقعی از دایرکتوری → کلیک روی کارت → پروفایل.
- اسکرین‌شات یا توصیف دقیق رفتار (شامل مسیر موتور نشان‌داده‌شده در UI).
- اگر خطای زنده‌ای دیدی: عیناً ثبت، نه تفسیر — بازبینی ممد خودش می‌خواند.
