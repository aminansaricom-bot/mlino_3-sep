# گزارش اصلاح برنامه‌ی اجرای MVP ملینو V2

تاریخ: ۲۰۲۶-۰۹-۱۱  
مبنای اصلاح: `MLINO_MVP_ARCHITECTURE_REVIEW.md`  
نوع تحویل: مستندات בלבד؛ بدون پیاده‌سازی

## اصلاحات اعمال‌شده

### ۱. مرز Permission

در `MLINO_MVP_EXECUTION_PLAN.md` روشن شد که MVP فقط می‌تواند Permission و Authorization موجود را اعتبارسنجی و مصرف کند.

به‌صراحت ثبت شد که MVP نمی‌تواند:

- Permission ایجاد کند؛
- Grant بسازد؛
- Membership یا Business Authority را تغییر دهد؛
- از Role، Consent، Parser، Context، Adapter یا نتیجه‌ی Matching به‌عنوان منبع اختیار استفاده کند.

همچنین نتیجه‌ی Gate به‌عنوان اجازه‌ی اجرای همان عملیات محلی در همان Session و Scope تعریف شد، نه اعطای اختیار جدید.

### ۲. ابطال Context و Matching

قاعده‌ی صریح اضافه شد:

اگر تغییر معنادار Context بر Intent یا Matching اثر بگذارد:

- Matching قبلی فوراً نامعتبر می‌شود؛
- ارزیابی مجدد با Context جاری الزامی است؛
- نتیجه‌ی قدیمی نمی‌تواند ادامه پیدا کند، نمایش داده شود یا انتخاب شود؛
- اجرای Matching تا تکمیل تأیید/ارزیابی لازم متوقف می‌ماند.

این قاعده در بخش اجرایی مسیر، معیارهای پذیرش Phase 1 و معیارهای پذیرش و آزمون‌های Phase 3 ثبت شد.

### ۳. Gate فاز صفر

به Phase 0 دو شرط خروج اضافه شد:

- دسترسی به متن و Revision دقیق ADR-0001 تا ADR-0012 پیش از شروع تغییر تولیدی بررسی و ثبت شود؛
- هم‌ترازی برنامه و پیاده‌سازی پیشنهادی با تصمیم‌های همان ADRها تأیید شود.

نبود متن ADR یا ابهام در Revision، خروج از Phase 0 را متوقف می‌کند. این شرط تصمیم معماری جدیدی ایجاد نمی‌کند و هیچ ADR را بازنویسی نمی‌کند.

## کنترل محدوده

- فقط اسناد تغییر کردند.
- MVP scope تغییر نکرد.
- معماری، مرز Core/V1/V2 و جهت محصول تغییر نکرد.
- کد تولیدی، Schema، API، قراردادها و ADRها تغییر نکردند.
- هیچ Feature، Persistence، Integration یا داده‌ی جدیدی اضافه نشد.
- Commit و Push این تحویل فقط شامل مستندات خواهد بود.
