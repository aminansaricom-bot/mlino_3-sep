# سند C (اصلاح‌شده) — مرزهای تولیدکننده‌ی Opportunity

**وضعیت: FREEZE CANDIDATE.** اصلاح‌شده از [OPPORTUNITY_PRODUCER_BOUNDARIES.md](../OPPORTUNITY_PRODUCER_BOUNDARIES.md). ساختار سه Value Engine (ظرفیت/کنسلی/پیگیری) بدون تغییر معتبر است؛ فقط ترمینولوژی، مکانیزم ثبت، و رویکرد بازیابی درآمد اصلاح شده‌اند.

---

## اصلاحیه‌ی ۱ — ترمینولوژی رسمی

هر «Value Engine» اکنون یک نمونه‌ی ثبت‌شده از نقش Kernel-سطح **تولیدکننده‌ی سیگنال دامنه (Domain Signal Producer)** است (طبق [MLINO_KERNEL_MINIMAL_AMENDMENT_VALUE_ENGINE_PRODUCERS.md](MLINO_KERNEL_MINIMAL_AMENDMENT_VALUE_ENGINE_PRODUCERS.md)). «Value Engine» نام محصولی/پیاده‌سازی این نقش باقی می‌ماند.

## اصلاحیه‌ی ۲ — الزام ثبت رسمی

هر سه Value Engine (و هر Value Engine آینده) باید در رجیستری تولیدکننده ثبت شوند پیش از این‌که مجاز به فراخوانی IC-۱۳ باشند — طبق ممنوعیت درگاه پشتی عمومی (IC-۱۳، بند ۱۶). این یک الزام جدید، سبک، و غیرقابل‌دور‌زدن است.

## اصلاحیه‌ی ۳ — اصلاح مسیر ورودی/خروجی

مسیر قبلی («فقط‌خواندنی از Capability ۱؛ فقط نوشتن از طریق IC-۱۳») اکنون دقیق‌تر است: خروجی هر Value Engine یک **Event Candidate**، نه یک Event پذیرفته‌شده، است. پذیرش نهایی پس از عبور از اعتبارسنجی محدود Capability ۲ اتفاق می‌افتد (طبق IC-۱۳، بند ۸). هیچ Value Engine نمی‌تواند ادعا کند «من حقیقت سازمانی نوشتم» — فقط «من یک موقعیت دامنه را تشخیص دادم و کاندیدا را از طریق قرارداد رسمی ارسال کردم».

## اصلاحیه‌ی ۴ — بازتعریف برداشت بازیابی درآمد (اصلاح جدی)

**یافته‌ی بازبینی نهایی (بخش ۱۶):** تفسیر پولی داخل Capability ۱ اصل «Kernel صنعت‌کور است» را نقض می‌کند.

**مدل اصلاح‌شده، دو لایه:**

| لایه | مالک | محتوا |
|---|---|---|
| تجمیع خام | Capability ۱ (Projection) | صرفاً شمارش/گروه‌بندی ساختاری Opportunityهای موجود بر اساس `domain_tag`/وضعیت — بدون معنای صنعتی |
| تفسیر پولی/صنعتی | لایه‌ی Feature/Domain Pack (همان لایه‌ی Value Engineها) | تبدیل شمار به برآورد ریالی — منطق دامنه، **نه** جزئی از Capability ۱ |

این هنوز به‌معنای «Value Engine مستقل جدید برای بازیابی درآمد» نیست — لایه‌ی تفسیر یک مؤلفه‌ی خواندنی (Read Model) است، نه یک تولیدکننده‌ی Event جدید؛ هیچ Event جدیدی نمی‌نویسد.

---

## بدون تغییر

مرز هر یک از سه Value Engine (ظرفیت، کنسلی/عدم‌حضور، پیگیری) — ورودی، منطق، خروجی — دقیقاً همان‌طور که در سند اصلی توصیف شده باقی می‌ماند.
